## 2. Physical Coach Boundary Attribution Tracing

### Where do verified coach boundaries come from?
In real deployed ARDS operations:
1. ARDS detects physical wheel-treadle pulses, optical axle-beam crossings, or wheel-detector triggers (`beam.csv.gz` / `inspections.jsonl`).
2. These events produce timestamped physical coach intervals:
   ```python
   coach_intervals = [
       {"coach_id": "C01", "start_frame": 120, "end_frame": 340},
       {"coach_id": "C02", "start_frame": 345, "end_frame": 570},
       ...
   ]
   ```
3. In `shadow_identity/shadow_ocr/frame_sampler.py:77-84`, as frames are sampled from the MP4:
   ```python
   if coach_intervals:
       for ci in coach_intervals:
           if ci["start_frame"] <= idx <= ci["end_frame"]:
               coach_id = ci["coach_id"]
               coach_source = "VERIFIED_BOUNDARY"
               break
   ```
4. If `coach_intervals` are **not provided** (e.g. standalone video playback without hardware beam metadata), `coach_id` is set to `None` and `coach_id_source` is set to `"UNVERIFIED"`.

### Explicit Fallback to Provisional
In `shadow_identity/shadow_ocr/consensus.py:175-182`:
```python
if result.coach_tracking_quality != "VERIFIED":
    result.visual_pair_status = "PAIR_PROVISIONAL"
    result.reason_codes.append("COACHES_UNVERIFIED_PAIR_PROVISIONAL_ONLY")
    return result
```
**Proof**: As demonstrated in `test_missing_coach_boundaries_prevents_pair_confirmed`, the consensus engine **never** outputs `PAIR_CONFIRMED` from frame repetition alone when boundaries are missing.
